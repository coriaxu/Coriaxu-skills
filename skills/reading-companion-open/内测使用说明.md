# 读书陪读 skill 内测使用说明

钟老师您好，这个包是一个“读书陪读搭档”skill。它不是用来一次性总结整本书的，而是陪你一段一段读：你发书摘、旧笔记或读后感，它先陪你聊；只有你明确说“存档”时，它才把这轮讨论整理成一张本地 Markdown 卡片。

## 这次想测什么

请重点观察四件事：

- 它会不会只围绕你当次发来的内容讨论，而不是跑去讲整本书。
- 它会不会在你说“存档”后先给预览，而不是直接写文件。
- 它会不会完整保留你的原话和作者原文，不把它们改成 AI 摘要。
- 它遇到旧笔记、换书、同名卡片、章节不确定时，会不会先问清楚。

## 准备一个测试文件夹

在电脑上新建一个空文件夹，例如：

```text
读书陪读内测
```

第一次启动时，AI 会问“读书笔记想放在哪个文件夹”。请把这个空文件夹路径给它。

如果您用 Obsidian，就回答“用 Obsidian”；不用的话回答“不用”。它会据此决定链接格式。

## 安装方式

如果您使用的工具支持 skill，把整个 `reading-companion-open` 文件夹放进对应的 skills 目录。

常见位置：

```text
Codex: ~/.codex/skills/reading-companion-open/
Claude Code: ~/.claude/skills/reading-companion-open/
```

如果您使用的是普通网页版 AI，不能安装 skill，就打开：

```text
references/prompt-only-version.md
```

把里面的“开场提示词”复制到新对话里，也能测核心体验，只是文件需要手动保存。

## 推荐测试脚本

### 1. 首次启动

对 AI 说：

```text
读书陪读
```

期望结果：

- 它只问两个问题：笔记文件夹、是否使用 Obsidian。
- 回答后，它创建配置文件和书架文件。
- 它问“这次想读哪本书？”

### 2. 新书陪读

告诉它一本书名，例如：

```text
陪我读《沉思录》。我想看看这本书怎么处理情绪和控制感。
```

再发一小段书摘和你的想法。

期望结果：

- 它围绕这段书摘讨论。
- 它不会主动做全书总结。
- 它会先回应你的理解，再补充自己的角度。

### 3. 存档

对 AI 说：

```text
存档
```

期望结果：

- 它先展示一张完整卡片预览。
- 预览里有“作者原文 / 我的分享 / AI 的延伸”三层。
- 它不会立刻写文件。

然后只回复：

```text
嗯
```

期望结果：

- 它不应该写文件，因为“嗯”不是明确确认。

再回复：

```text
确认，写入
```

期望结果：

- 它写入卡片。
- 它更新索引页和书架。
- 它只简短告诉你写了哪些文件，不复述整张卡。

### 4. 旧笔记回炉

发一条你以前写过的读书笔记，例如：

```text
这是我两年前写的旧笔记：我当时觉得这句话是在讲自律，但现在看可能更像是在讲人如何和不可控的事相处。

帮我回炉一下。
```

期望结果：

- 它把旧笔记当作旧材料，不改写旧笔记。
- 它给你当时可能没想到的新角度。
- 存档时使用“旧笔记回炉卡”，把“我之前的笔记”和“我今天的讨论”分开。

### 5. 换书和结读

对 AI 说：

```text
换一本，陪我读《悉达多》
```

期望结果：

- 它先问当前这本书要暂停还是结读。
- 它不会把两本书的卡片写到一起。

再对当前书说：

```text
这本书先放一放
```

或：

```text
这本书读完了，结读
```

期望结果：

- 暂停时，书架仍保留这本书但标记暂停。
- 结读时，书架把这本书移到“最近完成”。

## 反馈模板

测试后，麻烦按这个格式反馈，越具体越好：

```md
## 测试环境

- 使用工具：
- 是否能安装 skill：
- 笔记文件夹位置：

## 最顺的一点

[这里写实际体验]

## 最卡的一点

[这里写具体是哪一步卡住，最好贴原话]

## 生成的卡片是否可用

- 作者原文是否保留完整：
- 我的分享是否像自己说的话：
- AI 的延伸是否有增量：
- 索引和书架是否正确更新：

## 我希望它改进什么

[这里写建议]
```

## 注意事项

- 不需要上传整本书。每次发一小段原文或一条旧笔记就够。
- 不确定章节时，它应该写“章节待确认”，不能编。
- 这个 skill 不负责批量整理几百条笔记，也不负责写全书拆解报告。
- 测试时可以故意为难它，比如只回复“嗯”、发第二本书、保存同名卡片，看它会不会先问清楚。
