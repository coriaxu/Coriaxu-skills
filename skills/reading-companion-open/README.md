# reading-companion-open · 读书陪读（开源版）

把读书变成一段可持续的对话：边读边聊，聊出感觉就存档成卡，旧笔记随时回炉再生长。所有笔记落在你自己电脑的本地文件夹里——AI 工具只是执行者，换工具不丢任何东西。

## 它解决什么问题

你在 AI 里聊出过很精彩的读书讨论，但聊天记录会沉底：两周后你不会回去翻，翻也翻不到。这个 skill 把每一轮值得留下的讨论，按固定规矩落成本地 markdown 文件——书架、索引、卡片三层结构，由 AI 自动维护，你只负责读书和说"存档"。

## 安装

把整个 `reading-companion-open/` 文件夹放进你所用工具的 skills 目录：

- **Claude Code**：`~/.claude/skills/reading-companion-open/`
- **Codex**：`~/.codex/skills/reading-companion-open/`
- 其他支持 agent skills 的工具：放进对应的 skills 目录即可

不能装 skill 的环境（网页版 ChatGPT / Claude / Gemini）：用 [references/prompt-only-version.md](./references/prompt-only-version.md) 里的纯提示词版，核心体验一致，文件自己手工存。

## 首次使用

对 AI 说一句：

> 读书陪读

第一次使用时它会问你两个问题（笔记放哪个文件夹、是否用 Obsidian），然后自动建好书架文件和配置文件。之后告诉它你想读哪本书，就开始了。

## 日常用法

| 你说 | 它做 |
| --- | --- |
| `读书陪读` / `开启陪读` | 报书架，接上次进度 |
| 发一段原文 / 截图 + 你的感想 | 围绕这一段陪你讨论，一次讲一层 |
| 发一条以前写的旧笔记 | 回炉：重讲 + 给你当年没想到的角度 |
| `存档` | 把这轮讨论整理成卡片，预览确认后写入，自动更新索引和书架；同名卡片不会直接覆盖 |
| `换一本` | 先处理当前书的暂停或结读，再进入新书 |
| `这本书先放一放` | 标记暂停 |
| `结读` / `这本书完成了` | 归档：索引标记读完，书架挪入"最近完成" |

## 它写下的文件长什么样

```text
你的笔记库/
├── reading-companion.config.md   ← 配置（首次自动生成）
├── 00-当前加工书架.md             ← 仪表盘：在读哪些书、读完了哪些
└── 《某本书》/
    ├── 00-Index-某本书.md         ← 索引页：开读背景、读到哪、下次继续、卡片目录
    └── 主题句- 20260611.md        ← 一轮讨论 = 一张卡
```

样例见 [examples/](./examples/)。

给测试者的快速说明见 [内测使用说明.md](./内测使用说明.md)。

## 核心规矩（这个 skill 的灵魂）

- **一个对话只服务一本书**，每本书一条完整的线
- **说"存档"才动笔**，聊天阶段绝不写文件
- **先预览后写入**，你确认了才落盘
- **同名卡片不覆盖**，先问你是续写、改名还是另存
- **原文和你的原话一字不改**，AI 的延伸单独放层，三层不混
- **旧笔记回炉时时间层分开**，过去的笔记和今天的讨论不混区
- **查不到不硬编**，章节不确定就标"章节待确认"

## 不适合什么

一次性书籍摘要、批量笔记导入清洗、整本书拆解报告、课程共学（课程场景用 course-companion-open）。这套玩法适合精读和旧笔记回炉，不适合一年刷 50 本的泛读。

## 配置

全部配置项和示例见 [references/config-template.md](./references/config-template.md)。最常改的两项：`cards.template` 换 `full` 可启用六字段完整卡（加问题轨迹、行动线索、一句话结晶）；`library.link_style` 换 `wikilink` 适配 Obsidian。
